## Durable lessons (both recurred this session — worth watching)

1. **A second `#[tokio::test]` in one integration file kills the shared HTTP server.**
   My export-guard test started as a second `#[tokio::test]` in playground.rs; the
   harness gives each its own runtime, which drops and tears down the shared server when
   the first test finishes — flaking the pre-existing test at "help connect". The repo's
   documented idiom (graph_runtime.rs:527) is one booted `#[tokio::test]` per file with
   additional cases as sequential `async fn`s. Fixed by folding the export-guard case in.
   I hit this *despite* the in-code comment — the pattern is easy to miss.
2. **Read the gate result BEFORE committing; never `git add -A` on a feature commit.**
   I pushed `f9449797` on a red gate (`cargo test` exit 101) because I read the exit code
   while composing the commit rather than before it — self-corrected on the branch before
   any PR. And the unpin commit's `git add -A` swept the untracked memory auto-stub into
   the PR (Eric caught it); fixed with `git rm --cached` + amend + `--force-with-lease`.
   Both point to the same rule: stage explicit paths, and gate before commit — especially
   in these repos where the post-commit hook drops untracked memory stubs in the tree.
