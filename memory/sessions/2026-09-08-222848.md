## What happened

Lock-step twin of mercury-composable PR #332 (branch `feat/eq-operator` here as well):
the `eq` and `ne` simple plugins now compare **exactly two values** (consistent with
`gt`/`lt`; previously 2+ values chained all-equal-to-first), with optional 3rd/4th
modifier arguments — `ignoreCase` (two strings compare case-insensitively; non-string
values unaffected) and `ignoreType` (compares the `String.valueOf` text forms:
`"123" == 123`, `"123.456" == 123.456`, `"true" == true`); both together compare text
forms case-insensitively. Deliberate breaking change (Eric's spec): a 3rd plain value is
no longer chained equality — it must be a modifier.

Implementation notes (parity choices):

- Shared `equals_with_modifiers` helper in `crates/event-script/src/plugins.rs` mirrors
  Java `SimplePluginUtils.equalsWithModifiers`; `ne` stays the exact complement.
- Text form = the existing `conversions::display` (the documented `String.valueOf`
  analog: Nil → "null", floats keep the decimal point) — both for `ignoreType`
  comparison and for extracting modifier names.
- Case folding = `to_lowercase()` equality, the established idiom of the case-insensitive
  string operators (`startsWith`/`endsWith`/`includes`), rather than ASCII-only folding.
- Error strings match the Java engine exactly: the existing "Input is required to check
  for equality/inequality" for <2 args, new "Unknown modifier '{m}' - only 'ignoreCase'
  and 'ignoreType' are supported" and "Expected two values plus optional 'ignoreCase'
  and/or 'ignoreType' modifiers" (>4 args).
- Known pre-existing divergence (unchanged): rmpv collapses Integer/Long, so strict
  `eq(5, 5L)` is true here and false in Java boxing — indistinguishable on the wire.

Tests: new `eq_ne_modifiers_match_java_semantics` unit test in plugins.rs (strict /
ignoreCase / ignoreType / both-orders / exact error strings, incl. the removed chained
form); the `pluggableFunctions/types.yml` fixture re-mirrored byte-identical to the Java
repo (11 new rows) and `flow_runtime.rs` asserts all 11 new keys. Docs: the Rust
`docs/guides/event-script/syntax.md` plugin-table rows for `eq`/`ne` rewritten (this
repo's flow-schema-reference has no plugin table; claims registry pins nothing on eq/ne).
