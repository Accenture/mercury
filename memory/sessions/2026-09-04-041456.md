### The benchmark (Eric, this session)

**Doc discovery and token efficiency are the benchmark for the AI grammar** — the docs are what
make Human-AI collaboration work, so a map is only useful if an agent can pick the right page
from it in one hop and the map itself stays cheap to read. Measured for this change: the map
grows ~900 tokens (1,569 → 2,482) and routes to ~46k tokens of source-verified reference,
instead of a hunt through ~515k tokens of `crates/`. Entry style follows from this — dense with
the exact tokens an agent searches for (macro names, config keys, file names), and section
preambles that say *when* to open that section.

## The guard (done, same session — Eric approved)

This repo had **no `scripts/` directory and no docs check**, so nothing guarded the map. A
straight port of the Java repo's new coverage check (every guide must be listed) would be WRONG
here — the curated model intentionally omits ~20 pages. The right guard is **link integrity**,
now shipped as `scripts/check-llms-links.py`, run first in the docs workflow (no dependencies,
so it fails fast) with `scripts/**` added to the workflow triggers.

It enforces both conventions as actually written — markdown links from `docs/`, backticked repo
paths from the repo root — and excludes identifiers, bare filenames and URI schemes rather than
guessing. **The first draft flagged `classpath:/`, `file:/` and `flow://` as broken paths**; a
gate with false positives trains people to ignore it, so the rule was narrowed to exclude any
token containing `:`. Verified against three regressions: a mistyped link, a rotted backticked
path, and the original header defect written out (22 of 30 broken — it would have been caught
the moment it was introduced).
