## What happened

**Viability investigated and the draft port spec written for the sync-over-async
streaming return route** (`draft-design-specs/sync-over-async-port.md`, new thread
`ot-sync-over-async-port`). Eric asked whether a lock-step implementation of
progressive rendering is viable given (a) no Kafka module in this port, (b) no
embedded Redis for tests — the hand-rolled RESP double being acceptable if it fully
covers the use cases, with Pub/Sub flagged as the demanding part, and (c) Docker
intentionally not an option (VDI-class dev machines cannot virtualize).

Findings that shaped the spec:

- **No-Kafka is a non-blocker**: the streaming return route is broker-free by design
  (Java D3); Kafka only carried the Java demo's one-shot request leg. The one-shot
  pattern itself ships free as the degenerate stream (D8); only the Event Script
  facade tasks are deferred (spec Q1).
- **The substrate is already in lock-step**: `event_stream.rs` (EventStreamWriter,
  x-event-stream markers), the `stream: true` SSE edge with idle allowance, and the
  SSE consumer in `automation/http_client.rs` all exist — the missing piece is
  exactly the extension crate.
- **The RESP double is closer than feared**: it already speaks RESP2 over real TCP
  through the real `redis` crate and implements MULTI/EXEC with per-connection
  queueing — which lets the Rust store use `pipe().atomic()` instead of Java's Lua
  script (same atomic-append contract, no Lua interpreter to emulate). Needed
  extension ≈ 225 lines: Lists (value enum String|List), standalone EXPIRE, and
  Pub/Sub via per-connection mpsc + select (the one structural change:
  out-of-band-capable writes).
- **Emulated Pub/Sub is honest for THIS design** because wake-ups are best-effort by
  contract — lost notifications heal via drains, duplicates pop nothing; every
  invariant needing proof lives in the deterministic List/TTL/atomic surface. The
  Java chaos scenarios bypass publish entirely and port verbatim.
- **One real client delta**: redis-rs `aio::PubSub` (verified in the locked 1.5.0
  source) has no auto-resubscribe (Lettuce does) — the coordinator owns a
  reconnect/resubscribe loop plus one post-resubscribe recovery pass, which the
  existing final-drain machinery absorbs.
- **The prize**: wire-format parity (keys, envelope, channel naming, config keys —
  spec §4, normative) makes the rendezvous polyglot — Rust and Java pods sharing one
  streaming return route. Eric: "the interop is rewarding." Experiment R4 is that
  acceptance gate.

Spec follows the port-spec house format (status header, canonical source, maintainer
