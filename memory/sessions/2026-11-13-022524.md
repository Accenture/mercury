## Context

This repository was the Java Mercury's (1.x to 3.x) before the Rust port graduated into it on 2026-07-20, and it still
held 41 `release/*` branches plus `akka/v1-13-0` and `dev/v2-9-0`; tags began at `v4.9.0`. Eric asked for the approach
taken in mercury-composable on 2026-11-12 (its fact `historical-releases-tags-and-pages`) to be applied here: tag each
historical release, publish it as a GitHub release never marked latest, then delete the branches.

## What was done

- **Survey.** No branch tip carries `.github/workflows`, so neither a tag push nor a release event could start a
  workflow (GitHub reads both from the tagged commit); none ran. No ruleset, no protected branch. 40 tips carry their own
  version in their build files and CHANGELOG. Exceptions, settled with Eric:

    CHANGELOG goes 2.8.6 → 2.9.1). Eric: no `v2.9.0` tag or release; delete both branches (`v2.8.6` holds the commit).
  - `akka/v1-13-0` is the 1.13.0 release (4/23/2021, the release before 2.0.0). Eric: tag it `v1.13.0` like the others.
- **Tags.** 41 annotated tags `v1.12.8` ... `v3.0.19` and `v1.13.0` (dashed names normalized to dots), each at its
  branch tip, the tagger date the release commit's (`GIT_COMMITTER_DATE`), the message naming the branch and saying it is
