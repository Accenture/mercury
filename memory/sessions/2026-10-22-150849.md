## Summary

This is the Rust half of RFC-0010's WP3. The RFC lives in the Java repository, where WP1 and WP2 replace Jayway with an in-house
RFC 9535 engine. This engine keeps `serde_json_path`, which already implements the standard.

Eric's rulings, recorded in the RFC:
- a flow drops the task;
- a graph is rejected;
- one scanner finds where each reference lands;
- a simple plugin's `$` argument stays supported, because the Event Script syntax guide promises it (`syntax.md:1417` here), so
  the argument splitter is fixed;
- a `{reference}` never holds a JSONPath query.

What was built (branch `feat/jsonpath-refusal-rfc-0010`):
- `mlm.rs`: `compile_json_path` and `try_get_element`. A bad `$` path was a silent `None`; it is now
  `reason at position N of 'path'` on the mapping path and in the JSON-Path console.
- `jsonpath_source.rs`, the port of Java's `JsonPathSource`. Its reference spans copy this engine's own scans, which are left to
  right.
- The flow compiler and `model_validator.rs`, with the Java engine's messages word for word.
- The run-time `{$...}` refusal, in the substitution, in `assert_variables_resolved` and in `render_inexact_numbers`. DECIMAL
  renders a double before it substitutes, so the substitution alone would miss it.
- The splitter in `mapping.rs`.
- Tests:
  - `cts.json` against `serde_json_path`;
  - the shared `jsonpath-source-vectors.json`, 49 vectors;
  - parser flows 33 to 36;
  - six graph fixtures.
- CHANGELOG Unreleased Changed 5, and Increment 185.

Eric asked whether this engine already substitutes model variables before it parses a JSONPath. It does:
- `substitute_dynamic_index` runs before `get_lhs_element` (`executor.rs:948` and `:1473`);
- `substitute_mapping_source` runs at all six graph sites;
- a dictionary default is substituted on neither engine.

One difference is found: nested braces. For `{model.{model.k}}`, Java resolves the inner reference, while this engine pairs the
first `{` with the first `}` and inserts `null`. It is left for WP4.
