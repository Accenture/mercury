**Feature (http_client.rs):** `process_request` gained a stream target; when the
caller declared `Accept: text/event-stream` AND supplied a reply_to AND the upstream

(any bytes reset it, keep-alive comments included) — and forwards one
`x-event-stream: data` envelope per SSE event to the caller's reply route (head
control on the first: upstream status + SSE content type), `eof` on a clean end,
in-band `exception` on idle expiry (408 "Timeout for N seconds", engine-identical)
or mid-stream transport error (500). `SseParser`: byte-level incremental frame parser
(UTF-8-safe `\n` split, one-leading-space value strip, comment/id/retry suppression,
multi-line data join). Non-SSE responses on the candidate path keep the buffered
single-shot behavior byte for byte. Port idiom vs Java: the relay task frees the
client worker (Java frees its worker via the reactor subscription — same capacity
semantics); the head must still arrive within ttl+1 (Java exempts the head timer
entirely — a minor divergence in Rust's favor, documented in the increment).
