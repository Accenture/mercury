## Engine difference (documented, deliberate)

serde_json is **strict** where the Java engine's Gson is lenient: unquoted keys and
trailing commas are rejected here, accepted there (Gson's trailing comma silently
appends a null element). Both guides carry the difference; the portable-flow rule is
"use strict JSON". Same pattern as the UTF-16 vs Unicode-scalar `length` divergence.
