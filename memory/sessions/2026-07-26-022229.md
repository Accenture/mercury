## What changed

- `conversions.rs get_length`: `encode_utf16().count()` → `chars().count()`
  for strings and the display fallback; Binary stays bytes, Array stays
  element count, Nil stays 0 (encoding-independent, Java-identical).
- `plugins.rs plugin_substring`: char-based slicing (collected `Vec<char>`)
  replaces the `Vec<u16>` + `from_utf16_lossy` approach; out-of-bounds
  semantics and the exact error message unchanged (bounds now measured in
  scalar values). This RETIRES the retrofit's surrogate-split
  micro-divergence note — with scalar indexing there is no lossy case at all
  (Rust strings cannot hold unpaired surrogates, so exact Java parity was
  structurally impossible; the scalar story is cleaner than the retrofit
  ever was).
- Tests inverted to scalar semantics: `length_counts_unicode_scalar_values`
  (emoji = 1, a😀b = 3, 你好 = 2) and
  `substring_indexes_unicode_scalar_values` (emoji occupies ONE index;
  你好世界[0..2] == 你好; out-of-bounds at scalar length with the unchanged
  Java-wording message). All error-message parity tests untouched.
- Docs: syntax guide gains the "Rust port" note on the length/substring
  entries (identical for English/Chinese/BMP text; emoji counts 1 here, 2 in
  Java); CHANGELOG Unreleased gains the Changed entry recording the ruling.
