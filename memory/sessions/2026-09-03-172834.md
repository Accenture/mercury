Contributed a new example utility at Eric's direction, from the `ai-enabled-repo-demo` project

**`examples/minigraph-playground/scripts/playground-session-broker.mjs`** (+ `scripts/README.md`)
— a zero-dependency (Node ≥ 22) session broker that lets an **AI agent host** a Playground
session instead of borrowing a human's browser session, with humans joining via
`session subscribe <id>` as equal co-authors. It performs the web UI's own WS handshake
(`/ws/graph/playground`, `{"type":"welcome"}`, 20s ping/pong), parses the
`session ws-NNNNNN-N started` announcement, auto-reconnects with backoff across app restarts
(new id captured), and exposes a localhost-only control API (`GET /session`, `GET /console`,
`POST /start`, `POST /stop`, `POST /shutdown`; `--target` selects the app URL, `--port` the
control port).

The file is byte-identical to the copy contributed to the Java repo
(`~/sandbox/mercury-composable`), where it was smoke-tested against the running
`minigraph-playground` example: session hosting, companion `/sync` commands against the
broker-held session, keep-alive through ~5 idle minutes, and a full app kill/restart ridden out
by the reconnect loop. It was not separately run against the Rust engine this session, but
`ws_ui.rs` was inspected first and implements the same handshake (`session {public_id} started`,
identical ping/pong and welcome handling) — a Rust-side smoke test is the natural follow-up.
