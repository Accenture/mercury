- **Durable dependency decision — Redis crate: `redis` (redis-rs) v1.5.0.**
  Rationale: it is the official Rust Redis client (the redis-rs project),
  the most widely adopted and actively maintained; its `ConnectionManager`
  is the direct Lettuce analog the Java module uses — ONE shared
  multiplexed connection with automatic reconnection — realized lazily via
  a tokio `OnceCell::get_or_try_init` (a failed first connection is not
  cached; the next call retries, so the app boots normally without Redis
  and the first suspend/resume fails loudly instead). Explicit
  `cmd("SETEX")`/`cmd("GETDEL")` keep exact command parity with the Java
  module rather than relying on version-drifting convenience wrappers.
  Features: `tokio-comp` (the engine's runtime), `connection-manager`, and
  `tokio-rustls-comp` so `redis.ssl=true` works without OpenSSL. Every
  round-trip is bounded by `redis.timeout.ms` through a tokio timeout.
  Alternatives rejected: `fred` (clustering/pooling weight this store does
  not need, a second abstraction layer) and `deadpool-redis` (a pool is
  redundant over one multiplexed connection). `redis.*` config keys are
  shared with the sync-over-async family, all `${ENV_VAR:default}`-capable.

- **Engine independence held (both repos' rule):** the crate is imported by
  `examples/minigraph-playground` ONLY — Cargo dependency + a `main.rs`
  reference so the linker keeps the preload inventory + a startup log line.
  Live boot proof: the app compiles the 12 manifest tutorials through the
  P5-2 gate, both store functions register at 50 instances, and no Redis
  connection is attempted at boot (lazy).
