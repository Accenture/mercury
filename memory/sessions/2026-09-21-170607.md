**Method notes:**
- *Probe the client, don't trust its lexer.* librdkafka's `regexp.c` lexes `(?:` (L_NC),
  yet `subscribe("^(?:...)$")` fails "Invalid argument or configuration" — a throwaway
  six-variant probe test against `MockCluster` settled the anchor form in one run
  (`^(...)$` works), then was deleted. The Java-side lesson "verify by mechanism, not
  message" has a client-side twin: verify against the running client, not its source.
- `ConfigReader::get` substitutes `${...}` only when the `AppConfigReader` base exists
  (Java `baseConfig != null` parity) — a bare unit test sees the literal; the e2e's
  `${K2_HAPPY_GROUP:...}` group proves the substitution. Test at the right layer.
- rustfmt was NOT idempotent on `Some(x) => return Err(bad_config(&format!(...long...)))`
  arms: `cargo fmt` reflowed them and `--check` still failed. Restructuring the arms into
  `{ if ... { return Err(...) } value }` blocks made formatting stable. CI runs `--check`, so
  an unstable shape fails CI after a clean local fmt — run fmt THEN check before pushing.
